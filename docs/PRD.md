# PRD v0.1 — Android 设备跑机数据采集工具

> 状态：草稿（2026-10-19）
> 只写"要做什么 / 不做什么"，不写实现细节。
> **脱敏：本文件不出现公司名、项目名、内部路径清单、固件号、真实设备标识。**

---

## 一、形态决策（已定）

- **用户：只有我自己。** → **CLI（命令行工具），不做 GUI / Web UI。**
- 代价（明确接受）：没有界面、没有实时设备列表、没有点击式操作。
- 收益：工作量约为 Web UI 的 **1/3 – 1/5**；README 里一条命令 + 一段输出，就能被别人看懂。
- **因此砍掉：** 本地 Web 服务、浏览器界面、接口轮询、多设备实时刷新。

## 二、范围

### 要做的

1. **一条命令完成一次采集**：`python main.py --stage before|after`
2. **磁盘**：固定路径清单上的占用（单位 **K**，纯数字）
3. **内存 / 总磁盘**：各一个数字（单位 **M**）
4. **截图**：内存 / 磁盘各一张，按 `时间戳_命令名` 命名，落在 `out/<设备>/<日期>/`
5. **生成表格**：before / after 两栏 + 增长%
6. **自检**：开跑前验证 adb 可用、设备可识别、内部存储可读；不满足就**报错退出**

### 不做的（非目标）

1. **不自动化"配网步骤"**——那是 App 里连接设备的人工操作，ADB 做不到。工具只**提示**"配网是否已完成"，不代做。
2. **不做 GUI / Web UI。**
3. **不复刻任何已有工具的实现**：只借"需求事实"，不借代码、命名、模块划分、接口设计。
4. **不做多设备并发**：第一版只处理一台，串号显式传入。
5. **不做历史数据库**：第一版用"日期目录 + 文件"。

## 三、数据契约

| 项 | 规则 |
|---|---|
| 磁盘数值单位 | **K**（整数、纯数字、无单位字母） |
| 内存 / 磁盘总量单位 | **M** |
| 路径清单 | **外部配置文件**，不在仓库；程序只认清单里的路径 |
| 路径归一化 | 命令输出带前导 `/`，清单不带 → 填表前剥掉 |
| 阶段 | `before` / `after`，**必须显式指定**，不靠猜 |
| 增长% | `(after − before) / before`；**before = 0 时写"不可计算"**，绝不出现 `#DIV/0!` |
| 使用率判定 | 使用率 = used/total；**等于额定值不算超标**（用 `>` 判），提示语用 `≤` |

## 四、两个必须继承的设计

> 来自"看别人的工具跑出来的日志"得到的启发（只借鉴思路，不借实现）。

1. **命中率可观测**：清单 N 条、实际命中 M 条 → 打印 `命中 M/N`，并列出**未命中**的路径。
2. **缺失必须显式**：拿不到的值写空/`None` 并标注，**绝不用 0 冒充**。

## 五、失败处理

- adb 不可用 / 设备未授权 → **报错退出，不产生任何表格**
- 命令返回码非 0 → 抛错，不写表
- **stderr 出现 `Permission denied` → 这批数字标"不可信"，不写表**
- 截图失败 → 表照写，但标注"无截图"

## 六、验收标准（可测）

1. 一次完整采集后，表格 before / after 两栏都填满，增长% 无 `#DIV/0!`
2. 任意路径缺失 → 输出里有"未命中"清单，表格对应单元格**为空而非 0**
3. 设备未授权 → 命令失败，且**不生成表格文件**
4. 同一设备第二天再跑，能直接和前一天的数据对比
